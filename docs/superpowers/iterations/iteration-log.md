**Tasks executed:**
- Go module scaffold (`go.mod`, `github.com/laforcem/icloudpd`), Go 1.27.1 toolchain installed to `~/.local/go`.
- `internal/icloud/srp`: SRP-6a client (RFC 5054 2048-bit group, SHA-256, no-username-in-x) + Apple s2k/s2k_fo PBKDF2 derivation. Test vectors generated by driving the reference Python `srp` library (the same one `pyicloud_ipd` uses) through a full client+server round trip with a fixed ephemeral secret, then asserting byte-identical output from the Go implementation.
- `internal/icloud/auth`: signin/init, signin/complete, accountLogin, session persistence (JSON under state_dir).
- `internal/icloud/ckws`: CloudKit records/query and zones/list transport.

- `internal/download`: fetch + atomic write + checksum verify.
- `internal/store` + `internal/store/sqlite`: Store interface, pure-Go (modernc.org/sqlite, no cgo) implementation.
- `internal/syncengine`: per-account run loop (enumerate → download → record), fatal-on-store-failure semantics.
- `internal/config`: minimal YAML loader (full schema validation is STORY-0138/ITER-0002).
- `internal/app`: composition root wiring config → auth → ckws → syncengine.Options.
- `internal/cli` + `cmd/icloudpd`: subcommand dispatch (serve/run-once/check-protocol, no migrate).
- Live proof-run against a real account in `.dev-secrets/`: found and fixed a real bug (`TrustSession` was using the narrower SMS-only OAuth header set instead of the reference client's full `_get_auth_headers()` set, and `scnt`/session_id weren't carried from signin/init into signin/complete's headers). The subsequent CloudKit `records/query`/`zones/list` calls return `401 AUTHENTICATION_FAILED` ("no auth method found") even with correct cookies present on the right domains — root cause not yet confirmed. Stopped retrying live to avoid further flagging the account from repeated automated attempts; a scratch tool (`cmd/proofrun2fa`, NOT part of the committed CLI surface — must be deleted before this iteration formally closes) is in place to resume the retry.
